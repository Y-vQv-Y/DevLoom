# ADTEC DevLoom 企业全链路验收需求

## 1. 目的

本验收证明平台能在全新 Linux Docker 环境中，从 Web 输入业务需求，经模型生成前后端代码、
自动测试、任务状态回调和端口发布，最终通过 preview relay 提供可交互应用。只检查容器健康、
静态首页或固定 Todo 示例均不算通过。

## 2. 验收项目：Delivery Control Center

为 ADTEC 数字化运营团队生成一个交付运营中心，满足：

- 展示跨项目总工作量、进行中、阻塞、完成率和项目进度；
- 管理工作项的标题、项目、负责人、优先级、状态、截止日和估算点数；
- 支持按关键字、状态和优先级筛选；
- 支持创建工作项和推进 `planned -> active -> review -> done` 生命周期；
- 使用 SQLite 持久化，进程重启后数据仍存在；
- 每次写操作记录 action、entity、actor、detail 和 UTC 时间；
- 提供 `/healthz`、`/api/summary`、`/api/work-items`、`/api/audit`；
- 前端必须响应式、可创建和推进工作项，API 路径必须兼容 preview 前缀；
- 不依赖公网 CDN 或在线包管理器。

## 3. Agent 任务要求

在 Web 新建任务并输入上述需求，选择已验证的模型、在线主机和 devbox。Agent 必须实际执行：

1. 写入后端、前端、自动测试和项目 README；
2. 编译/语法检查；
3. 运行后端单元与 HTTP 集成测试；
4. 以 `0.0.0.0:8000` 启动服务；
5. 用 HTTP 创建工作项、更新状态、筛选并查询审计事件；
6. 发布端口 8000；
7. 正常结束任务并把状态回调为 completed。

## 4. 平台级证据

- Web 登录、模型、镜像、主机和任务均来自本次全新安装；
- 任务事件中存在文件写入、测试命令、服务启动和端口发布；
- 任务文件 API 能列出生成文件并读取内容；
- preview GET 返回前端，POST/PATCH 经 relay 到达同一工作区；
- 中心和 Runner 重启后 VM/任务路由仍可恢复；
- 主 TGZ 与包内 23 个文件清单均通过 SHA-256；
- 包内含中心镜像、Taskflow、preview、Orchestrator、devbox 和可读安装脚本；
- 包路径不含专利材料、密钥、构建缓存和外部应用包目录。

## 5. 失败判定

以下任一情况均需修复并从头重跑：模型名不可用、任务未完成、生成代码未测试、服务只监听
localhost、preview 仅 GET 可用、写操作未持久化、审计缺失、Runner 未认证、重启丢路由、
安装仍需公网、清单提交号不是最终 HEAD，或最终包不是最新代码构建。
